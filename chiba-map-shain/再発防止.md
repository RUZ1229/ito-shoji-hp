## 二系統の正本

| 系統 | フォルダ | 用途 |
|------|----------|------|
| **社内** | `AI化/千葉配送地図/` | 伊藤商事社内 |
| **他社** | `AI化/千葉配送地図_他社/` | 他社・副社長等（配布先ラベルが違うだけではない） |

- **UI・JS・CSS** … 原則 **両フォルダ同内容**（機能追加時）。開発正本は `千葉配送地図_他社/` → ビルド時に社内へ同期可。
- **データ** … `data/map_overrides.json` **系統ごと**。差を付けるときはここ（または系統専用設定）だけ。

## 意図的な差分（現時点）

**許されているのはマーカー凡例の 2t／4t 表示の有無のみ**（`map_overrides.json` の `marker_legend` 等）。

| 項目 | 社内 | 他社 | 備考 |
|------|------|------|------|
| 2t専用（三角） | あり | あり | 現状同一 |
| 4t専用（四角） | **あり** | **なし** | 社内のみ（柏2T+5O 等） |

**ビルド注意** … `_sync_shain_ui_from_tasha()` は **css/js/index のみ**同期。**data/ は上書きしない**（9/7 に data まで同期して 4t が消えた事例あり）。

**オンラインURL** … `live_url_社内.txt`（`chiba-map-shain/`）／ `live_url_他社.txt`（`chiba-map/`）

**それ以外**（コース統合・仮想ピン・合言葉・オンラインURL・新機能の片方だけ実装等）は、**社長が明示するまで両方同じ**にする。

---

## 機能追加の手順（原則）

1. `千葉配送地図_他社/` で実装・確認
2. **同じ変更を** `千葉配送地図/` に反映（または `build_chiba_map_distrib_pack.py` の同期）
3. `build_chiba_map_data.py` … **省略時は両系統**の `map_data.json` を更新
4. zip・オンライン公開 … 配布パック生成 → `deploy_chiba_map_live.sh`（必要時）
5. 社長報告 … **両方更新したか**、**意図的差分を入れたか** を1行で書く

**片方だけ・差分あり** … 社長の明示指示がある場合のみ。

## 事例1（2026-09-07）— URL共通化の副作用

**症状** … 9/7にオンライン版を1URLに寄せ、ルール・READMEに「中身同一」「配布先ラベルのみ」と記載。社長から「二系統でないと片方だけ機能追加できない」と指摘。

**原因** … 配信の簡略化と系統の概念を混同。再発防止メモ未整備。

**対策** … 本メモ作成。`.cursor/rules/千葉配送地図-二系統.mdc` を社長方針に合わせて修正。**機能は原則両方、差分は2t/4tのみ（社長指示まで）。** `_sync_shain_ui_from_tasha()` で **data 上書きを停止**。

---

## 事例2（2026-09-07）— 社内 4t 消失

**症状** … 社内 map にあった 4t専用（四角）凡例・柏2T+5O の square が消え、他社と同一になっていた。

**原因** … `_sync_shain_mirror_from_tasha()` が **data/ ごと**他社→社内に上書き。他社は 4t なし設計のため社内も消えた。

**対策** … 社内 `map_overrides.json` を復元（square・4t凡例）。同期は **UI のみ**（css/js/index）。オンラインも **URL2本**（`chiba-map-shain` / `chiba-map`）。

**確認** … 社内 `map_data.json` に `"square": "4t専用（四角）"` あり。他社に square なし。
